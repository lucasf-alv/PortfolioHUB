# Colaboração e Versionamento

## 1. Objetivo

Documentar as práticas de versionamento, compartilhamento
e colaboração utilizadas no PortfolioHUB.

## 2. Ferramentas

- Git: controle de versão local.
- GitHub: hospedagem e compartilhamento do repositório.
- GitHub Pages: publicação do portfólio.
- Markdown: documentação técnica.

## 3. Fluxo de versionamento

O fluxo de trabalho utilizado é:

1. Modificar ou criar arquivos localmente.
2. Verificar as alterações com git status.
3. Revisar as diferenças com git diff.
4. Adicionar os arquivos com git add.
5. Registrar as alterações com git commit.
6. Enviar os commits com git push.
7. Verificar a publicação no GitHub.

## 4. Padrão de commits

As mensagens de commit devem ser curtas e descrever
a finalidade da alteração.

Exemplos:

- feat: adiciona nova funcionalidade
- docs: atualiza documentação
- fix: corrige problema
- style: ajusta apresentação visual
- test: adiciona ou atualiza testes

## 5. Versionamento por tags

Tags Git identificam versões importantes do projeto.

Exemplo:

- v1.0: versão inicial da página.
- v1.1: primeira evolução funcional ou visual.
- v2.0: futura versão com mudanças significativas.

As tags devem corresponder a versões realmente registradas
no histórico do projeto.

## 6. Compartilhamento

O repositório público permite que outras pessoas consultem
o código e a documentação.

Link do repositório:
https://github.com/lucasf-alv/PortfolioHUB

Link do site:

## 7. Colaboração

Se o projeto passar a receber contribuições, as alterações
deverão ser revisadas antes de serem incorporadas à branch
principal.

Para trabalhos colaborativos, podem ser utilizadas branches
e pull requests.

## 8. Segurança

Somente pessoas autorizadas devem receber permissão de escrita.

Credenciais e informações sensíveis não devem ser publicadas.

## 9. Validação

O processo será validado verificando o histórico de commits,
as tags, a sincronização com o GitHub e a publicação do site.
